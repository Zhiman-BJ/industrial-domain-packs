# Chip Pack provenance

The `eda-harness/` subtree is based on the private `Zhiman-BJ/eda-harness` repository at commit `9842ba787230e7bee2de37056594d567ee925d31` (version 0.6.0), with the `0.6.1` patch set. It contains the shared EDA Core, the 25-tool MCP server, its Skill and Kimi adapter source, pinned Python lockfile, and the Docker tool-image build inputs. Project examples and PDK data are not part of the MCP distribution.

The patch set adds bounded container cleanup and recovery, per-user admission across projects sharing a Docker daemon, compiler/thread limits, execution evidence and diagnostics, and mapped-memory equivalence adapters. The tool-image changes retain fixed upstream binaries, add pinned Z3, replace the nonportable Kepler ORFS callback with a real Yosys proof, and repair the pinned IHP export's functional-cell removal pattern. The registered provider source digest identifies the patched subtree; it must be regenerated whenever that source changes. This patch is not the upstream 0.7.0 release. See [runtime changes and qualification](eda-harness/docs/runtime-reliability.md).

The Linux installer preview.2 additionally runs local Linux Docker execution with the caller's UID/GID, so root-owned container outputs do not break host checkpoint persistence. Its registered executable snapshot SHA-256 is `95448c85231f7e8abb6ccbfb8facde03e77350fb2a19f84f50a07a3b93e0044d`. The earlier runtime-fixes evidence records the previous snapshot; the installer release's verification identifies and qualifies this updated snapshot.
