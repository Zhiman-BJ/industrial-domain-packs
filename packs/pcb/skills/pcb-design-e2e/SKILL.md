# PCB design E2E

Start with `project_status`: inspect actual CAD, immutable public requirements and stale checks. Large requirements return a section index; use `project_status(requirements_path=...)` to read the relevant JSON pointer and follow `next_call` while `has_more`. `run_analysis` already runs the fixed public tests. `spec.json` is editable design intent; it cannot change task acceptance. Choose topology, parts, values, placement and routing wherever requirements leave those decisions open. Explain major choices and repairs with a short engineering reason and the check that will test it. Tool execution success is separate from a design verdict.

Follow the requested scope: inspection, local repair, simulation or full delivery. For a focused task, finish after the requested checks and a factual report; export bundles and submit claims only when the task requires them. Aggregate UNKNOWN outside that scope is a reported limitation, not a reason to repeat passing checks or expand the task.

`inspect_tool(name)` gives current argument schemas and a stable output schema. The runtime can expose the same canonical tools by capability group (`core`, `components`, `schematic`, `pcb`, `verification`, `delivery`) using `PCB_TOOL_GROUPS` or the API `--groups` option. Prefer the smallest groups needed for the current stage to reduce selection burden; an empty selection keeps the full compatibility registry. Use named operations for CAD; one call edits one component, connection, path or property. Engine calls generate, route, fill or verify a stage. Use `list_references`/`read_reference` for the focused references below. No task answers or preferred coordinates are supplied by this skill.

## Build and verify

1. **Requirements and existing work.** For a new design, use `new_project` and record additional design constraints with `set_requirements`. For repair, inspect the supplied project first. Uncompiled briefs permit diagnostic work; missing independent coverage prevents completion PASS. Missing seed files are an environment problem, not an instruction to invent the repair input.
2. **Parts and facts.** Search, then `inspect_symbol` for canonical pin numbers and `lookup_component` for sourced MPN facts/models. `add_component` adds a disconnected symbol. `add_net` declares a network; `connect_pin` attaches one pin. Pin names/metadata are not connections. `add_no_connect` marks an intentionally unused, disconnected pin. `configure_component(ref,properties={"symbol":...})` retains used pin numbers or rejects the change; review electrical meaning afterward.
   Missing parts use `prepare_component` → `qualify_component` → `install_component`; `bind_model` installs qualified terminal mappings. Symbol/pad creation tools make CAD drafts, not qualified devices. Read [tools.md](references/tools.md) for intake schemas and [standards.md](references/standards.md) for the KiCad baseline. When a URL returns HTML, use `discover_artifacts`, select the matching source link, then `fetch_artifact` and `read_datasheet`. Missing evidence stays explicit.
3. **Schematic and circuit checks.** Generate the schematic, inspect it, then `verify_schematic`. Its `schematic_requirements` verdict covers only that stage; `electrical_status` and final qualification are separate. ERC, exported netlist/intent parity and actual symbol/footprint pin mapping are different checks. PWR_FLAG describes a real supply path; neither a flag nor an added jumper proves a circuit electrically correct. Use `inspect_schematic` and the schematic pose/field/wire tools for local drawing corrections. Moving a unit preserves UUIDs and netlist or refuses the edit. Wire edits can change connectivity: rerun ERC and netlist parity. Regeneration retains existing unit poses and identities but may redraw wires.
4. **Applicable analyses.** Read [analysis.md](references/analysis.md), check `project_status.analysis_readiness`, then run the required analyses at the appropriate stage. Schematic SPICE needs actual connectivity, explicit models/stimuli and assertions. Final evidence must bind to the current board and inputs. Candidate-authored tests remain diagnostics. Missing models, backends or measurements mean UNKNOWN, never a candidate-authored N/A. Only the fixed external requirements can approve exemptions. An empty postroute object supplies no verification.
5. **PCB and layout.** Generate the PCB after schematic checks; missing electrical evidence allows only the authorized prototype/diagnostic scope. Review [layout.md](references/layout.md) before placement. Plan functional groups, mechanical anchors and current/return paths; choose poses from actual pad/footprint geometry. Generated packing is a starting arrangement. Place staged footprints inside the outline before routing. Keep schematic drawing coordinates, board placement and viewer framing separate. After circuit edits, regenerate the schematic and use `update_pcb` to preserve unaffected copper.
6. **Routing and repair.** `add_track(points=...,net_name=...,width_mm=...)` creates one continuous path and `add_arc(start=...,mid=...,end=...,net_name=...,width_mm=...)` creates one native KiCad copper arc; the model chooses the geometry. Both retain UUIDs and require a fresh DRC. Freerouting adopts only a DRC-passing candidate. To repair a retained failure, use `checkout_board` with its path and both current/candidate hashes, then run DRC to obtain current UUIDs. Checkout preserves a rollback board and is not acceptance. Fill zones before evaluating them. Unrelated copper must not touch on a shared layer; crossing on separate layers needs an interconnect to become a connection. Read [advanced-cad.md](references/advanced-cad.md) for hierarchy, differential paths, tuning and assembly.
7. **Requested delivery.** Follow the fixed task's deliverables: use `prepare_3d_model` and `export_3d` when assembly evidence is required, `export_project` for a revision-bound CAD/Gerber/drill/BOM/CPL bundle, or `save_project_copy` for retained CAD without acceptance claims. Submit `finalize_claims` only when the task requires structured claims; it runs `verify_design` freshly, so avoid an unchanged duplicate final check. A local repair that requires checks and a report finishes with those. Read warnings by actual type: dangling copper and hole spacing are not silkscreen warnings. `set_component_text` adjusts PCB reference/value fields without moving the footprint.

## Local repair and evidence boundaries

Before editing, locate the failing reference/pin/net or complete UUID, sheet/layer and verified coordinates. `inspect_schematic` returns revision-bound pages: follow `next_call` or select a complete ref/UUID. A partial sheet cannot prove absent wires or labels. The controller requires current coverage before editing existing native CAD, including previously unseen hierarchy sheets; whole-sheet regeneration requires all affected sheet objects. Missing, incomplete or stale coverage returns executable observation queries. PCB object edits need a current target observation; routing needs a complete affected-net copper query, while whole-board edits need all collections. A complete local target remains editable without reading unrelated sheets. Copper-preserving `update_pcb` needs the current complete parts query, not every board collection; follow the specific queries in an observation error. `inspect_board(item_id=...)` returns one current object. For complete copper or pad observations use `collection` with optional layer, net or spatial bounds, then follow revision-bound `next_call`; footprint `children_query` retrieves its pads. Bounds and endpoint statistics are geometric observations. Native DRC checks physical shorts and unconnected items; schematic/PCB parity checks declared pin/pad/net membership separately. Refresh stale findings. For value or topology changes, establish the relevant electrical baseline first; a geometric DRC finding alone does not justify changing circuit behavior. Distinguish measured facts from hypotheses. Retrieve missing evidence before relying on it; state the suspected cause, make the smallest justified edit, rerun the affected check, and inspect newly introduced failures. Final measurements and counts must cite the current revision. A reduced error count is insufficient if required connectivity was removed. Keep unrelated parts and copper. Use [agent-loop.md](references/agent-loop.md) for candidate checkout, interruptions and resume.

Read test statuses and condition hashes with `project_status(check_stage=...)`; these receipts remain distinct from aggregate qualification. Avoid repeating unchanged checks solely to retrieve their fields. `UNCHANGED` means no edit occurred; it does not justify regeneration. A passing check needs no corrective edit; an exempt check needs no substitute evidence.

Every public observation has `status`, `scope` and `next_action`; native checks additionally expose `available`, `report_valid`, violations and report paths when applicable. A successful tool process is not a check PASS, and an inspection observation carries `verification_role=observation_only`. For a compressed verification report, read `check_summary` and its JSON pointers to locate each status and direct cause. Follow omitted entries in the saved report before explaining an aggregate UNKNOWN; a missing electrical model does not by itself explain a CAD verdict. Report only the observation coverage actually returned. When the runtime signals its closing window, preserve the current board and finish with the available evidence and remaining blockers.

The harness may continue the same session after a transient provider failure within its original time/step budget. Inspect current state before acting; interrupted tool calls are reconciled rather than replayed. After an abnormal exit, read `operation_outcome`: `CHANGED_REVIEW_REQUIRED` means files changed despite process failure. Inspect the current CAD and UUIDs before another mutation; do not replay the edit blindly or restart the design. Preserve original requirements and the failed evidence. Stop at a concrete missing dependency or exhausted budget.

Use `view_design` for revision-bound native views. Only an adapter that actually delivers the image supports model visual review; text-only models must rely on measured geometry. A partial sheet/front-layer view cannot prove other sheets, layers or assembly geometry correct. Empty thinking fields mean the provider supplied no readable text; do not invent it.

Report CAD delivery, declared simulations and hardware qualification separately. `scoped_status` covers fixed requirements only. A behavioral SPICE model does not establish commercial device qualification, supply-current/power balance, all operating corners or stability. Geometry checks do not prove impedance, return paths or EMC; field simulation does not establish product compliance. Read [verification.md](references/verification.md) for acceptance, [numerical.md](references/numerical.md) for solver scope and [kicad-python-traps.md](references/kicad-python-traps.md) only when diagnosing native API issues.

`run_python` is a read-only candidate/report calculator, with derived output under `PCB_EXTENSION_SCRATCH`. It cannot read evaluator/controller source, edit CAD, spawn subprocesses or use the network. Missing public operations are capability gaps, not a reason to bypass the boundary. Factory adaptation and ordering are outside this environment.
